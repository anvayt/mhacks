- **additive + clarified errors**, P2/P3 (wave 7, dev `de8ccdb`), acks: P1 [ ] P2 [x] P3 [ ] P4 [ ]
  - `POST /compare`: each listing may supply `session_id` instead of address/url. The saved estimate is used with its existing answers. A failed side preserves the original HTTP status and `detail.code`, `message` and optional `hint`, adding `detail.listing: "a" | "b"`. This supersedes wave 2's historical `estimate_failed` description; it does not replace the underlying error code. Model/lookup failures use friendly user-facing text.
  - `GET /health` exposes API liveness and model availability separately. A healthy API does not imply the model is reachable.
  - Public guarded requests default to **120 per IP per 60 seconds**, configurable with positive integer `RATE_LIMIT_PER_MIN`. `GET /commitments/suggested` (including property routes) and plain `GET /leaderboard/position` (including property routes) are exempt. A position query containing `catalog_ids` still counts because it can run a projection. The separate photo limit remains three per ten minutes; the streamed body cap remains 8 MiB of base64 photo plus 64 KiB JSON overhead.
  - Only a valid, nonempty `X-Agent-Key` bypasses rate limits. The agent now includes it on every API call; browser requests never include it. The body cap still applies to agent calls. The demo launcher builds and starts the production web; it no longer uses `next dev`.
